# Security policy

Do not open a public issue for a suspected vulnerability or exposed credential.
Use the repository host's private vulnerability-reporting feature. Until a remote
is configured, record the finding locally in an encrypted note and rotate affected
credentials before sharing diagnostic material.

Supported releases are the newest tagged minor release only. Reports should include
the affected version, deployment mode, minimum reproduction and impact. Never attach
live tokens, cloud account identifiers, customer documents or full production logs.

The project treats authentication bypass, cross-project data access, arbitrary tool
execution, approval bypass, backup corruption and supply-chain substitution as
critical severity.
